## 1. Overview

This document describes the end-to-end licensing system used across all Qalibrated Systems products. It covers how licenses are generated by the Lante ERP, verified by client applications, controlled remotely, and how every licensable hardware peripheral and software module is gated.

### Design Principles

- **Unforgeable** — Licenses are ES256 JWTs signed with an EC P-256 private key that never leaves the ERP server. Decompiling the client app yields only the public key, which cannot produce valid signatures.
- **Per-app** — One license for `qalitrack-frontend` cannot activate `qalitrack-mobile` or any other app.
- **Per-feature** — Each hardware peripheral and software module is an independent feature flag in the token. A customer pays for only what they use.
- **Expiry-enforced** — Every license has an explicit `exp` claim enforced locally (no network needed).
- **Remotely revocable** — The ERP exposes `/api/v1/licenses/validate`. The app calls it on activation and daily. Revoking from the ERP UI locks the app within 24 hours.
- **Offline-tolerant** — A 7-day grace period lets apps work without network. After 7 days the app locks.
- **Machine-bound (optional)** — A license can be pinned to one machine via MAC + hostname fingerprint. Using it on another machine fails immediately.
- **Validated both ends** — The backend rejects unknown feature flags and app IDs at issue time. The frontend rejects unknown feature values at dev time. Typos are impossible in production.

## 3. Two-Layer Gate Model

### Layer 1 — AppLicenseGate (whole app)

Wraps the entire React tree in `App.jsx`. The app shows nothing until a valid license is activated.

```jsx
// App.jsx
<AppLicenseGate>
  <BrowserRouter>...</BrowserRouter>
</AppLicenseGate>
```

**States:**

| State | What the user sees |
|---|---|
| `null` | Spinner — checking cached license |
| `valid` | App renders normally |
| `not_activated` | Full-screen lock, token input, Machine ID displayed |
| `expired` | Lock screen with "expired" banner, token input for renewal |
| `revoked` | Lock screen with "revoked" banner |
| `machine_mismatch` | Lock screen — token is for a different machine |

### Layer 2 — FeatureLicenseGate (per module)

Wraps individual tabs or pages. Only renders if the active license includes the named feature.

```jsx
import { LicenseFeatures } from "../../utils/LicenseFeatures";
import FeatureLicenseGate from "../../components/FeatureLicenseGate";

<FeatureLicenseGate feature={LicenseFeatures.ANPR}>
  <AnprSettings />
</FeatureLicenseGate>
```

If the feature is not in the token, the user sees a locked placeholder with a contact email — not an error.

**Dev-time safety:** passing an unknown string to `feature` logs a console error in development mode listing all valid values. Impossible to silently ship a typo.

## 4. Machine ID

### How it is derived

In Electron, the machine ID is computed in the **main process** (Node.js, full OS access):

```
base64( hostname + ":" + primary_MAC_address )
  .replace(/[^a-zA-Z0-9]/g, "")
  .slice(0, 24)
```

It is then **written to `<userData>/machine-id`** on first run and read from there on subsequent runs.

### Persistence across reinstalls

| Scenario | Machine ID |
|---|---|
| App reinstalled (same OS, same hardware) | **Same** — userData directory survives NSIS uninstall |
| App updated | **Same** — userData is never touched by updates |
| New network card / MAC changes | **New** — re-derived from new hardware |
| OS reinstalled / new machine | **New** — new hardware fingerprint |
| Customer asks "why am I locked out after reinstall?" | Check if hardware changed. If not, userData was manually deleted — re-issue the same license |

### Where the renderer gets it

The main process exposes it via IPC through the preload script:

```js
// electron/preload.cjs
contextBridge.exposeInMainWorld('electronAPI', {
  getMachineId: () => ipcRenderer.invoke('get-machine-id'),
});
```

`AppLicenseGate` calls `getMachineIdAsync()` on mount, which calls `window.electronAPI.getMachineId()`. The result is cached in `_machineIdCache` for the rest of the session.

### What the customer needs to do

1. Open QaliTrack → sees the lock screen
2. Copies the **Machine ID** displayed on screen (Copy button provided)
3. Sends it to Qalibrated Systems
4. ERP admin pastes it in the Machine ID field when issuing → license is hardware-bound

Leaving Machine ID blank in the ERP = **floating license** (works on any machine).

## 5. Feature Flags

### Complete catalogue

Both `LicenseFeatures.cs` (backend) and `LicenseFeatures.js` (frontend) define these. Adding to one without the other will cause the frontend gate to warn and the backend to reject.

#### Hardware peripherals

| Constant | JWT value | Hardware |
|---|---|---|
| `ANPR` | `anpr` | Automatic Number Plate Recognition / NPR camera |
| `BOOM_BARRIER` | `boom_barrier` | Boom barrier / gate controller |
| `REMOTE_DISPLAY` | `remote_display` | Remote Display Unit — large LED in driver's cab line |
| `TRAFFIC_LIGHT` | `traffic_light` | Traffic light controller — red/green lane signals |
| `AXLE_DETECTOR` | `axle_detector` | Vehicle position / axle sensors — detects truck on scale |
| `TICKET_PRINTER` | `ticket_printer` | Thermal ticket printer |
| `RFID` | `rfid` | RFID reader — card/tag identification |
| `NFC` | `nfc` | NFC reader — short-range tap identification |

#### Software modules

| Constant | JWT value | Module |
|---|---|---|
| `KIOSK` | `kiosk` | Self-service weighbridge kiosk terminal |
| `DUAL_LANE` | `dual_lane` | Dual lane / second independent weighbridge |
| `SMS_ALERTS` | `sms_alerts` | SMS gateway — automated driver/manager alerts |
| `REPORTS` | `reports` | Advanced report builder |
| `ANALYTICS` | `analytics` | Analytics dashboard — charts, trends, KPIs |
| `API_ACCESS` | `api_access` | External API — third-party system integration |

### Using constants in code (mandatory)

```js
// ✅ Correct — typo-safe, autocompleted, validated at dev time
import { LicenseFeatures } from "../../utils/LicenseFeatures";
<FeatureLicenseGate feature={LicenseFeatures.BOOM_BARRIER}>

// ❌ Wrong — bare string, silent typo in production
<FeatureLicenseGate feature="boom_barier">
```

### Adding a new feature

1. Add constant to `LicenseFeatures.cs` (`Core/Constants/`) — backend validates on issue
2. Add constant to `LicenseFeatures.js` (`src/utils/`) — frontend validates at dev time
3. Wrap your module: `<FeatureLicenseGate feature={LicenseFeatures.YOUR_FEATURE}>`
4. No migration needed — features are stored as `TEXT` in the existing `features` column

## 7. JWT Token Structure

### Header
```json
{ "alg": "ES256", "typ": "JWT" }
```

### Payload
```json
{
  "iss": "qalibrated.co.ke",
  "sub": "KTDA-001",
  "app": "qalitrack-frontend",
  "features": ["anpr", "boom_barrier", "kiosk"],
  "iat": 1744588800,
  "exp": 1776124800,
  "mid": "S2VueWF0dGE6YWI6Y2Q"
}
```

| Field | Required | Description |
|---|---|---|
| `iss` | yes | Always `"qalibrated.co.ke"` |
| `sub` | yes | Customer ID from Lante ERP CRM |
| `app` | yes | App identifier — client rejects if it doesn't match |
| `features` | yes | Array of licensed feature flags |
| `iat` | yes | Issued-at unix timestamp |
| `exp` | yes | Expiry unix timestamp — enforced locally and server-side |
| `mid` | no | Machine ID — if present, any other machine is rejected |

### API Endpoints

| Method | Path | Auth | Description |
|---|---|---|---|
| `GET` | `/api/v1/licenses/metadata` | None | Returns all valid app IDs and feature catalogue |
| `POST` | `/api/v1/licenses/validate` | None | Client check-in — validates token, updates LastSeen |
| `POST` | `/api/v1/licenses` | Bearer | Issue a new license |
| `GET` | `/api/v1/licenses` | Bearer | List licenses (filterable by app, customer, active) |
| `GET` | `/api/v1/licenses/{id}` | Bearer | Get single license |
| `GET` | `/api/v1/licenses/expiring` | Bearer | Licenses expiring within N days |
| `DELETE` | `/api/v1/licenses/{id}` | Bearer | Revoke a license |

### Validation on issue

The `POST /api/v1/licenses` endpoint rejects:
- Unknown `appId` → 400 with list of valid values
- Unknown feature strings → 400 with list of valid values
- `expiresAt` in the past → 400

### Database schema (`licensing.licenses`)

```sql
id              TEXT PRIMARY KEY
token           TEXT UNIQUE NOT NULL   -- full JWT string
customer_id     VARCHAR(100) NOT NULL
customer_name   VARCHAR(255)
app_id          VARCHAR(100) NOT NULL
features        TEXT NOT NULL          -- comma-separated, e.g. "anpr,kiosk"
machine_id      VARCHAR(255)           -- null = floating
issued_at       TIMESTAMPTZ NOT NULL
expires_at      TIMESTAMPTZ NOT NULL
revoked         BOOLEAN NOT NULL DEFAULT false
revoke_reason   VARCHAR(500)
last_seen       TIMESTAMPTZ            -- updated on each check-in
last_machine_id VARCHAR(255)           -- last machine that checked in (audit)
notes           TEXT
created_by      TEXT
updated_by      TEXT
is_deleted      BOOLEAN NOT NULL DEFAULT false
```

### Key pair

```
Algorithm:  EC P-256 (ES256)
Private key: stored in environment variable  License__PrivateKeyJwk
             set in docker-compose.yml / Azure Key Vault / appsettings
Public key:  embedded in client app  src/utils/licenseUtils.js → PUBLIC_KEY_JWK
```

**Private key JWK (never commit, ERP only):**
```
{"kty":"EC","crv":"P-256","x":"KYOOP-qgdZetRUtcTWPQthev2oXwwtkCRtCerL_L3qw","y":"CxlCG84CG7YL8VwOO9s8p5tm8kO0GxB0rmO_WiTIIcg","d":"SfRNrvaz2nFcVm7CYOZLj7ipQqhTum5EYqvmBNMueuA"}
```

**If the private key is compromised:** generate a new pair (`node src/utils/generateKeyPair.mjs`), update `PUBLIC_KEY_JWK` in all apps (requires app update + re-deploy), re-issue all customer licenses.

## 9. Client-Side Implementation

### Files

| File | Purpose |
|---|---|
| `electron/main.cjs` | Machine ID derivation, IPC handler, preload setup |
| `electron/preload.cjs` | Exposes `window.electronAPI.getMachineId()` to renderer |
| `src/utils/licenseUtils.js` | JWT verification (ECDSA), cache, server check-in |
| `src/utils/LicenseFeatures.js` | Constants for all feature flags — use these, never bare strings |
| `src/components/AppLicenseGate.jsx` | Full-app lock screen — wraps entire React tree |
| `src/components/FeatureLicenseGate.jsx` | Per-module gate — validates one feature flag |
| `src/utils/generateKeyPair.mjs` | One-time key pair generation script |

### License flow on first launch

```
App opens
  └─ AppLicenseGate mounts
       └─ getMachineIdAsync()  →  IPC  →  main.cjs reads userData/machine-id
       └─ getLicenseStatus("")
            └─ readCache()  →  no cached token
            └─ returns { valid: false, reason: "not_activated" }
       └─ Shows full-screen lock with Machine ID + token input

User pastes token → activateLicense(token)
  └─ verifyLicenseToken(token)   [local, instant]
       └─ ECDSA signature check
       └─ exp check
       └─ app claim check  (must match "qalitrack-frontend")
       └─ mid check  (if present, must match getMachineId())
  └─ checkWithServer(token)  [network, ~1s]
       └─ POST /api/v1/licenses/validate
       └─ ERP checks: not revoked, not expired, correct app+machine
  └─ writeCache({ token, features, expiresAt, customerId, ... })
  └─ setStatus({ valid: true, ... })  →  app unlocks
```

### License flow on subsequent launches

```
App opens
  └─ AppLicenseGate mounts
       └─ readCache()  →  cached token found
       └─ verifyLicenseToken(token)  →  valid locally
       └─ background server check if cache > 24h old (non-blocking)
       └─ App renders immediately

Every 60 seconds (live expiry check):
  └─ getLicenseStatus("")
       └─ if expired/revoked  →  setStatus(locked)  →  lock screen appears
```

### Offline grace period

If the server is unreachable during check-in:
- Token is locally valid → app continues
- `warning: "offline_grace"` flag is set after server failure
- Grace period: **7 days** from `cachedAt`
- After 7 days with no server contact: `valid: false` → lock screen

## 11. Operational Runbook

### Issue a new license

1. Customer opens QaliTrack → lock screen → copies **Machine ID** (if hardware binding needed)
2. ERP → Licensing → Issue New License
3. Fill in Customer ID, Name, App (`qalitrack-frontend`), check features, set expiry
4. Paste Machine ID if hardware binding required (leave blank for floating)
5. Click Issue → copy the JWT token → send to customer by email
6. Customer pastes token in app → activates immediately

### Renew an expiring license

1. ERP → Licensing → find the license
2. Issue a **new** license with the same fields and a new expiry date
3. Send the new token — the old one remains expired and invalid
4. Customer pastes the new token in the lock screen

### Add a feature to an existing license

Issue a **new** license with the original features **plus** the new one. The old token continues working until the customer activates the new one (it overwrites the cache).

### Revoke a license immediately

1. ERP → Licensing → find license → Revoke → enter reason
2. The next time the app checks in (up to 24h) it will lock
3. For instant effect: ask the customer to open the app (which triggers an immediate check-in on startup)

### Customer reinstalls the app — same machine

Machine ID is derived from hardware and persisted in `%APPDATA%\Qalitrack\machine-id`. Reinstalling the app does **not** delete this file. The customer's existing token will work after reinstall with no action needed.

### Customer gets a new machine

New hardware = new Machine ID = old machine-bound license is rejected. Issue a new license with the new Machine ID. The old license can be revoked.

## 12. Security Considerations

| Threat | Mitigation |
|---|---|
| Attacker decompiles app | Only public key in app — cannot forge signatures |
| Attacker copies token to another machine | `mid` claim rejects it immediately (local check, no network needed) |
| Attacker modifies localStorage | Token re-verified on every activation and every 60s while running |
| Customer shares floating token | Server detects unusual `LastMachineId` changes — can revoke |
| License stolen in transit | Send over encrypted email / ERP portal (HTTPS only) |
| Private key leaked | Rotate key pair, push app update with new public key, re-issue all licenses |
| Offline bypass | Grace period hard-capped at 7 days — after that app locks regardless |
| Unknown feature string in token | Backend rejects at issue time; frontend warns at build time |
